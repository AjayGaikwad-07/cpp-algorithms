Bubble Sort

Easy

📖 Definition

Repeatedly compares adjacent elements and swaps them if they are in the wrong order. The largest element "bubbles up" to its correct position in each pass.

Passes required = n - 1
Comparisons in pass i = n - i

⚡ Complexity

CaseTime
BestO(n)
AverageO(n²)
WorstO(n²)
SpaceO(1)
Stable ✅ In-Place ✅

🎬 Visualize: Array [64, 34, 25, 12, 22]

Press Run to start animation
🔢 Numerical Problem
Q1: Sort the array [29, 10, 14, 37, 13] using Bubble Sort. Show all passes.
Pass 1:
[29, 10, 14, 37, 13] → swap 29,10 → [10, 29, 14, 37, 13] → swap 29,14 → [10, 14, 29, 37, 13] → no swap → [10, 14, 29, 37, 13] → swap 37,13 → [10, 14, 29, 13, 37]
Pass 2:
[10, 14, 29, 13, 37] → swap 29,13 → [10, 14, 13, 29, 37]
Pass 3:
[10, 14, 13, 29, 37] → swap 14,13 → [10, 13, 14, 29, 37]
Pass 4:
[10, 13, 14, 29, 37] → no swaps → ✅ [10, 13, 14, 29, 37]
💡 Key: Total swaps = 5. Array is sorted in 4 passes (n-1).

🌟 Extra Information

📌 Best case O(n) when array is already sorted (with optimization flag)
📌 Called "Bubble" because smaller elements rise to top like bubbles
📌 Used in educational contexts; rarely in production code
📌 Optimization: Stop early if no swaps occurred in a pass
C++ Implementation
void bubbleSort(int arr[], int n) {
    for (int i = 0; i < n-1; i++) {
        bool swapped = false;
        for (int j = 0; j < n-i-1; j++) {
            if (arr[j] > arr[j+1]) {
                swap(arr[j], arr[j+1]);
                swapped = true;
            }
        }
        if (!swapped) break; // Optimization
    }
}
02

Selection Sort

Easy

📖 Definition

Finds the minimum element from the unsorted part and places it at the beginning. Divides the array into sorted and unsorted partitions.

Total comparisons = n(n-1)/2
Always exactly n-1 swaps

⚡ Complexity

CaseTime
BestO(n²)
AverageO(n²)
WorstO(n²)
SpaceO(1)
Unstable ❌ In-Place ✅
🔢 Numerical Problem
Q1: Apply Selection Sort on [64, 25, 12, 22, 11]. Show each selection and swap.
Step 1: Min in [64,25,12,22,11] = 11 → swap with 64 → [11, 25, 12, 22, 64]
Step 2: Min in [25,12,22,64] = 12 → swap with 25 → [11, 12, 25, 22, 64]
Step 3: Min in [25,22,64] = 22 → swap with 25 → [11, 12, 22, 25, 64]
Step 4: Min in [25,64] = 25 → no swap → [11, 12, 22, 25, 64]
✅ Final: [11, 12, 22, 25, 64]
💡 Total swaps = 3 (much fewer than bubble sort!)

🌟 Extra Information

📌 Makes minimum number of swaps — good when memory write is costly
📌 NOT stable — equal elements may change relative order
📌 Performance doesn't improve for sorted arrays
📌 Useful for small arrays or embedded systems with limited writes
C++ Implementation
void selectionSort(int arr[], int n) {
    for (int i = 0; i < n-1; i++) {
        int minIdx = i;
        for (int j = i+1; j < n; j++)
            if (arr[j] < arr[minIdx])
                minIdx = j;
        swap(arr[minIdx], arr[i]);
    }
}
03

Insertion Sort

Easy

📖 Definition

Builds sorted array one element at a time. Picks each element and inserts it into its correct position among previously sorted elements — like sorting playing cards!

Best: Already sorted → O(n)
Online algorithm — works on streams

⚡ Complexity

CaseTime
BestO(n)
AverageO(n²)
WorstO(n²)
SpaceO(1)
Stable ✅ In-Place ✅ Online ✅
🔢 Numerical Problem
Q1: Sort [12, 11, 13, 5, 6] using Insertion Sort step by step.
i=1: key=11, 12>11 → shift → Insert 11 → [11, 12, 13, 5, 6]
i=2: key=13, 12<13 → no shift → [11, 12, 13, 5, 6]
i=3: key=5, shift 13,12,11 → Insert 5 → [5, 11, 12, 13, 6]
i=4: key=6, shift 13,12,11 → Insert 6 → [5, 6, 11, 12, 13]
💡 Key element is compared and shifted until correct position found

🌟 Extra Information

📌 Excellent for nearly-sorted arrays (adaptive)
📌 Used in practice as part of Timsort (Python's built-in sort)
📌 Works well on small data sets (n ≤ 20)
📌 Online: can sort while receiving elements
C++ Implementation
void insertionSort(int arr[], int n) {
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j+1] = arr[j];
            j--;
        }
        arr[j+1] = key;
    }
}

📌 Used to count inversions in an array
C++ Implementation
void merge(int arr[], int l, int m, int r) {
    int n1 = m-l+1, n2 = r-m;
    int L[n1], R[n2];
    for(int i=0;i<n1;i++) L[i]=arr[l+i];
    for(int j=0;j<n2;j++) R[j]=arr[m+1+j];
    int i=0,j=0,k=l;
    while(i<n1 && j<n2)
        arr[k++] = (L[i]<=R[j]) ? L[i++] : R[j++];
    while(i<n1) arr[k++]=L[i++];
    while(j<n2) arr[k++]=R[j++];
}
void mergeSort(int arr[], int l, int r) {
    if(l < r) {
        int m = l+(r-l)/2;
        mergeSort(arr, l, m);
        mergeSort(arr, m+1, r);
        merge(arr, l, m, r);
    }
}

Quick Sort

Medium

📖 Definition

Selects a pivot, partitions array into elements smaller and larger than pivot, then recursively sorts each partition. Partition step is key!

Partition: place pivot at correct index
Left part < pivot < Right part

⚡ Complexity

CaseTime
BestO(n log n)
AverageO(n log n)
WorstO(n²)
SpaceO(log n)
Unstable ❌ In-Place ✅ Cache-friendly ✅

🎯 Partition Example: [10, 80, 30, 90, 40, 50, 70] pivot=70

Initial:
10803090405070(P)
After partition:
10304050708090
🔢 Numerical Problem
Q1: Sort [3, 6, 8, 10, 1, 2, 1] using Quick Sort with last element as pivot. Show partition step.
Pivot = 1 (last element)
i = -1, scan array:
j=0: 3>1, skip
j=1: 6>1, skip
j=2: 8>1, skip
j=3: 10>1, skip
j=4: 1≤1, i++→i=0, swap arr[0]↔arr[4] → [1,6,8,10,3,2,1]
j=5: 2>1, skip
j=6: pivot reached → swap arr[i+1]↔arr[6] → swap arr[1]↔arr[6]
After partition: [1, 1, 8, 10, 3, 2, 6]
Pivot (1) now at index 1. Recurse on [1] and [8,10,3,2,6]
Final: [1, 1, 2, 3, 6, 8, 10] ✅
💡 Worst case O(n²) occurs when pivot is always min/max (sorted array)

🌟 Extra Information

📌 Fastest in practice due to cache locality
📌 Randomized pivot avoids worst case
📌 Used in C++ std::sort (Introsort = Quick + Heap + Insert)
📌 3-way partition handles duplicate keys efficiently
C++ Implementation
int partition(int arr[], int low, int high) {
    int pivot = arr[high], i = low - 1;
    for (int j = low; j < high; j++)
        if (arr[j] <= pivot)
            swap(arr[++i], arr[j]);
    swap(arr[i+1], arr[high]);
    return i + 1;
}
void quickSort(int arr[], int low, int high) {
    if (low < high) {
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}

Heap Sort

Hard

📖 Definition

Uses a Binary Max-Heap data structure. First builds a max-heap, then repeatedly extracts the maximum element to sort the array.

Build Max-Heap: O(n)
Extract n times: O(n log n)
Total: O(n log n)

⚡ Complexity

CaseTime
BestO(n log n)
AverageO(n log n)
WorstO(n log n)
SpaceO(1)
Unstable ❌ In-Place ✅

🌳 Max-Heap Structure: [4, 10, 3, 5, 1]

10
5
3
4
1
Array: [10, 5, 3, 4, 1] → Parent(i) = (i-1)/2
🔢 Numerical Problem
Q1: Sort [4, 10, 3, 5, 1] using Heap Sort. Show heapify steps.
Phase 1: Build Max-Heap
Start from last non-leaf = index 1
Heapify(1): 10>5, 10>4 → no swap needed for 10
Heapify(0): 4<10 → swap 4,10 → [10,4,3,5,1]
Heapify(0) again: 4<5 → swap → [10,5,3,4,1] ← Max-Heap

Phase 2: Extract Max Repeatedly
Swap arr[0]↔arr[4]: [1,5,3,4,|10] → Heapify → [5,4,3,1,|10]
Swap arr[0]↔arr[3]: [1,4,3,|5,10] → Heapify → [4,1,3,|5,10]
Swap arr[0]↔arr[2]: [3,1,|4,5,10] → Heapify → [3,1,|4,5,10]
Swap arr[0]↔arr[1]: [1,|3,4,5,10] → done
✅ Final: [1, 3, 4, 5, 10]
💡 Heapify is O(log n). Building heap is O(n) not O(n log n)!

🌟 Extra Information

📌 Guaranteed O(n log n) in all cases — advantage over QuickSort
📌 In-place sorting — advantage over MergeSort
📌 Not cache-friendly → slower in practice despite same complexity
📌 Used in Priority Queues and scheduling algorithms
C++ Implementation
void heapify(int arr[], int n, int i) {
    int largest = i, l = 2*i+1, r = 2*i+2;
    if (l < n && arr[l] > arr[largest]) largest = l;
    if (r < n && arr[r] > arr[largest]) largest = r;
    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}
void heapSort(int arr[], int n) {
    for (int i = n/2-1; i >= 0; i--)
        heapify(arr, n, i);   // Build max heap
    for (int i = n-1; i > 0; i--) {
        swap(arr[0], arr[i]); // Move root to end
        heapify(arr, i, 0);   // Re-heapify
    }
}

🤑 Greedy Algorithms

Making locally optimal choices for globally optimal solutions

💡

What is Greedy?

A greedy algorithm makes the locally optimal choice at each step with the hope that these local choices will lead to a globally optimal solution. It never reconsiders choices made in past steps.

✅ Greedy Choice Property ✅ Optimal Substructure ⚠️ May not always work

Activity Selection Problem

Easy

📖 Definition

Given n activities with start and finish times, select the maximum number of non-overlapping activities. Sort by finish time and greedily pick activities that don't conflict.

Greedy Choice: Always pick activity
with earliest finish time!

⚡ Complexity

OperationTime
SortingO(n log n)
SelectionO(n)
TotalO(n log n)
SpaceO(1)
🔢 Numerical Problem
Q1: Given activities with start and finish times:
A1(1,4), A2(3,5), A3(0,6), A4(5,7), A5(3,9), A6(5,9), A7(6,10), A8(8,11), A9(8,12), A10(2,14), A11(12,16)
Find the maximum number of activities.
Step 1: Sort by finish time
A1(1,4), A2(3,5), A3(0,6), A4(5,7), A5(3,9), A6(5,9), A7(6,10), A8(8,11), A9(8,12), A10(2,14), A11(12,16)

Step 2: Apply Greedy Selection
Select A1(1,4) ← first activity (earliest finish)
A2(3,5): start=3 < finish=4 → SKIP (overlaps A1)
A3(0,6): start=0 < finish=4 → SKIP
Select A4(5,7) ← start=5 ≥ 4 ✅
A5,A6: start < 7 → SKIP
Select A8(8,11) ← start=8 ≥ 7 ✅
A9: start=8 < 11 → SKIP
A10: start=2 < 11 → SKIP
Select A11(12,16) ← start=12 ≥ 11 ✅
✅ Maximum activities = 4 → {A1, A4, A8, A11}
C++ Implementation
void activitySelection(int s[], int f[], int n) {
    // Sort by finish time first
    cout << "Selected: A1"; // First activity always selected
    int prev = 0;
    for (int i = 1; i < n; i++) {
        if (s[i] >= f[prev]) {
            cout << ", A" << i+1;
            prev = i;
        }
    }
}

Fractional Knapsack

Medium

📖 Definition

Given items with weights and values, and a knapsack with capacity W. Can take fractions of items. Goal: maximize total value. Greedy: sort by value/weight ratio and take greedily.

Ratio = Value / Weight
Sort by ratio (descending)
Take items until bag is full

⚡ Complexity

OperationTime
SortingO(n log n)
FillingO(n)
TotalO(n log n)
Greedy Works ✅ 0/1 Knapsack uses DP
🔢 Numerical Problem
Q1: Knapsack capacity W=50. Items: (w=10,v=60), (w=20,v=100), (w=30,v=120). Find maximum value.
Step 1: Calculate Value/Weight Ratios
Item 1: 60/10 = 6.0
Item 2: 100/20 = 5.0
Item 3: 120/30 = 4.0

Step 2: Sort by Ratio (desc): Item1 > Item2 > Item3

Step 3: Fill Greedily (W=50)
Take all of Item1 (w=10): remaining=40, value=60
Take all of Item2 (w=20): remaining=20, value=160
Take 20/30 of Item3: value += (20/30)×120 = 80
✅ Maximum Value = 60 + 100 + 80 = 240
💡 Fraction taken = (remaining capacity) / item weight × item value

🌟 Extra Information

📌 Greedy works for FRACTIONAL but NOT 0/1 Knapsack
📌 0/1 Knapsack requires Dynamic Programming
📌 Real world: cargo loading, investment portfolio
📌 Optimal substructure + greedy choice = greedy is optimal

Hard

📖 Definition

A lossless data compression algorithm. Assigns shorter binary codes to more frequent characters using a greedy approach with a min-heap priority queue.

Encode frequent chars with fewer bits
Build tree bottom-up (min freqs first)
Left=0, Right=1

⚡ Complexity

OperationTime
Build treeO(n log n)
SpaceO(n)
Lossless ✅ Prefix-free codes ✅

Job Sequencing with Deadlines

Medium

📖 Definition

Given jobs with deadlines and profits, schedule jobs to maximize profit. Each job takes 1 unit time. Greedy: sort by profit (desc) and schedule each job in latest available slot before its deadline.

Breadth-First Search (BFS)

Easy

📖 Definition

Explores graph level by level using a Queue. Visits all neighbors of a node before going deeper. Finds shortest path in unweighted graphs.

Uses QUEUE (FIFO)
Level 0 → Level 1 → Level 2...
Shortest path in unweighted graph

⚡ Complexity

RepresentationTime
Adjacency ListO(V+E)
Adjacency MatrixO(V²)
SpaceO(V)
Shortest path ✅ Level traversal ✅

🎯 BFS Traversal Example

BFS from node 0
🔢 Numerical Problem
Q1: Graph with edges: 0-1, 0-2, 1-3, 1-4, 2-4. Perform BFS from vertex 0. Show queue state at each step.
Init: Queue=[0], Visited={0}
Step 1: Dequeue 0, Visit neighbors 1,2 → Queue=[1,2], Visited={0,1,2}, Output: 0
Step 2: Dequeue 1, Visit neighbors 3,4 → Queue=[2,3,4], Visited={0,1,2,3,4}, Output: 0 1
Step 3: Dequeue 2, neighbor 4 already visited → Queue=[3,4], Output: 0 1 2
Step 4: Dequeue 3 → Queue=[4], Output: 0 1 2 3
Step 5: Dequeue 4 → Queue=[], Output: 0 1 2 3 4
✅ BFS Order: 0 → 1 → 2 → 3 → 4
💡 BFS gives shortest path (in terms of edges) from source to all vertices
C++ Implementation
void BFS(vector<vector<int>>& adj, int start, int V) {
    vector<bool> visited(V, false);
    queue<int> q;
    visited[start] = true;
    q.push(start);
    while (!q.empty()) {
        int v = q.front(); q.pop();
        cout << v << " ";
        for (int u : adj[v])
            if (!visited[u]) {
                visited[u] = true;
                q.push(u);
            }
    }
}

Dijkstra's Algorithm

Medium

📖 Definition

Finds shortest path from a source to all vertices in a graph with non-negative weights. Uses a min-heap (priority queue). Greedy — always relaxes the closest unvisited vertex.

dist[v] = min(dist[v], dist[u] + w(u,v))
⚠️ Fails with negative edges!

⚡ Complexity

ImplementationTime
ArrayO(V²)
Binary HeapO((V+E) log V)
Fibonacci HeapO(E + V log V)
No negative edges ❌ Greedy ✅
🔢 Numerical Problem
Q1: Find shortest paths from vertex 0.
Graph: 0→1(4), 0→2(1), 2→1(2), 1→3(1), 2→3(5)
Init: dist[] = [0, ∞, ∞, ∞], PQ={(0,0)}
Extract (0,0):

🌟 Extra Information

📌 Used in GPS navigation, network routing (OSPF protocol)
📌 Fails for negative weight edges — use Bellman-Ford instead
📌 Single-source shortest path algorithm
📌 For all-pairs shortest paths, use Floyd-Warshall
C++ Implementation
void dijkstra(vector<pair<int,int>> adj[], int V, int src) {
    vector<int> dist(V, INT_MAX);
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
    dist[src] = 0;
    pq.push({0, src});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;
        for (auto [v, w] : adj[u])
            if (dist[u]+w < dist[v]) {
                dist[v] = dist[u]+w;
                pq.push({dist[v], v});
            }
    }
}

Bellman-Ford Algorithm

Medium

📖 Definition

Finds shortest paths from a single source, even with negative weight edges. Relaxes all edges V-1 times. Also detects negative cycles.

Repeat V-1 times:
For each edge (u,v,w):
dist[v] = min(dist[v], dist[u]+w)

⚡ Complexity

OperationTime
TimeO(VE)
SpaceO(V)
Negative edges ✅ Neg cycle detect ✅ Slower than Dijkstra
🔢 Numerical Problem
Q1: Graph (directed): 0→1(6), 0→2(7), 1→2(8), 1→3(-4), 1→4(5), 2→4(-3), 3→0(2), 4→3(7). Source=0. Find shortest distances.

Iteration 1:
0→1(6): dist[1]=6
0→2(7): dist[2]=7
1→3(-4): dist[3]=6+(-4)=2
1→4(5): dist[4]=6+5=11

dist = [0, 6, 7, 2, 4]
Iteration 2:
3→0(2): 2+2=4 > 0, no update
4→3(7): 4+7=11 > 2, no update
No changes → converged!

🌟 Extra Information

📌 Used in routing protocols like RIP (Routing Information Protocol)
📌 Can handle negative weights — Dijkstra cannot
📌 Detects negative cycles — runs 1 extra iteration to check
📌 Dynamic Programming approach (unlike Dijkstra's greedy)

C++ Implementation (Union-Find)
int find(int parent[], int i) {
    if (parent[i] != i) parent[i] = find(parent, parent[i]);
    return parent[i];
}
void kruskalMST(vector<tuple<int,int,int>>& edges, int V) {
    sort(edges.begin(), edges.end()); // Sort by weight
    vector<int> parent(V), rank(V,0);
    iota(parent.begin(), parent.end(), 0);
    int cost = 0;
    for (auto [w, u, v] : edges) {
        int pu = find(parent.data(), u);
        int pv = find(parent.data(), v);
        if (pu != pv) { // No cycle
            cost += w;
            if (rank[pu] < rank[pv]) swap(pu, pv);
            parent[pv] = pu;
            if (rank[pu] == rank[pv]) rank[pu]++;
        }
    }
    cout << "MST cost: " << cost;
}

C++ Implementation
void floydWarshall(int dist[][V]) {
    for (int k = 0; k < V; k++)
        for (int i = 0; i < V; i++)
            for (int j = 0; j < V; j++)
                if (dist[i][k] != INF && dist[k][j] != INF)
                    dist[i][j] = min(dist[i][j], dist[i][k]+dist[k][j]);
    // Check negative cycles:
    for (int i = 0; i < V; i++)
        if (dist[i][i] < 0) cout << "Negative cycle!";
}

Pattern searching, preprocessing tables, and linear-time string matching!

01

Naive String Matching (Brute Force)

Easy

📖 Definition & Concept

Slides pattern $P$ of length $M$ over text $T$ of length $N$ one character at a time. At every shift $s \in [0, N-M]$, compares characters from left to right until a mismatch occurs or full pattern matches.

Valid Shifts: $s = 0, 1, 2, \dots, N-M$
Total Shift Windows: $N - M + 1$
Worst-Case Comparisons: $(N - M + 1) \times M \approx O(N \times M)$

⚡ Complexity

CaseTime
Best CaseO(N)
Average CaseO(N)
Worst CaseO((N-M+1) × M)
SpaceO(1)
No Preprocessing ✅ Backtracks text pointer ⚠️
🔢 Numerical / Dry-Run Problem

02

Knuth-Morris-Pratt (KMP) Algorithm

Optimal / Advanced

📖 Core Intuition & LPS Array

KMP achieves strictly linear time $O(N + M)$ by taking advantage of the pattern's self-similarity. It builds the LPS (Longest Proper Prefix which is also Suffix) table $\pi[0 \dots M-1]$ during preprocessing so that the text pointer $i$ never backtracks.

Mismatch at $P[j] \neq T[i]$:
• If $j > 0 \implies j \leftarrow \text{LPS}[j-1]$ (text index $i$ stays unchanged!)
• If $j == 0 \implies i \leftarrow i + 1$

⚡ Complexity

PhaseTimeSpace
LPS PreprocessingO(M)O(M)
Search PhaseO(N)O(1)
Total Worst-CaseO(N + M)O(M)
Strict Linear Time ✅ Zero Text Backtracking ✅
🔢 Numerical: Compute LPS ($\pi$) Array
Q2: Construct the complete LPS (Longest Prefix Suffix) table for the pattern $P = \text{"ABABCABAB"}$.
Index $j$012345678
$P[j]$ABABCABAB
LPS$[j]$001201234

Explanation:
• $P[0..2] = \text{"ABA"} \implies$ Proper prefix "A" == suffix "A" (len 1).
• $P[0..3] = \text{"ABAB"} \implies$ Proper prefix "AB" == suffix "AB" (len 2).
• $P[0..4] = \text{"ABABC"} \implies$ No proper prefix matches suffix $\implies \text{LPS}[4] = 0$.
• $P[0..8] = \text{"ABABCABAB"} \implies$ Prefix "ABAB" matches suffix "ABAB" (len 4).
